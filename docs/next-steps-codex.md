# Промпт за Codex — довършване и проверка на RePoint Етап 1

Работиш в директорията на RePoint. Това е дипломна работа със строго индивидуално задание за монолитно ASP.NET Core MVC уеб приложение, SQL Server и EF Core Code First. **Не сменяй темата и не добавяй микросървиси.** Прегледай `README.md`, `docs/requirements-traceability.md`, документацията и съществуващия код преди промени.

1. Използвай .NET 10 LTS (минимум .NET 8 по задание), EF Core 10, MS SQL Server. Провери restore/build и поправи всички компилационни грешки. Ако се наложи корекция в проекта, опиши я в отчет.
2. Провери Razor изгледите, SQL Server настройките, Identity и всички модели/индекси. Никакви реални пароли в git. Настрой конфигурацията чрез `dotnet user-secrets`.
3. Създай действителната **EF Core Code First начална миграция** `InitialCreate` с `dotnet ef migrations add InitialCreate --project src/RePoint.Web --startup-project src/RePoint.Web --output-dir Data/Migrations` и я запиши в git. Не използвай `EnsureCreated` и не подменяй EF миграцията с SQL скрипт.
4. Стартирай SQL Server локално или в Docker с парола само от локална среда. Изпълни `dotnet ef database update` и провери таблиците, първичните/външните ключове, уникалния индекс `ConfirmedDeliveries.HandoverRequestId` и seeded material/point demo rows.
5. Стартирай приложението и провери Home, Points, Materials, Campaigns, Identity Register/Login, Requests/Create, Requests/Index, 404 и 500. Провери филтрите по град и материал и достъпа на неавтентикирани потребители.
6. Стартирай тестовете. Генерирай coverage отчет за бизнес логиката; 65% line coverage е **финално изискване**, не твърди, че е изпълнено без измерване. Добави CI проверки и отчети.
7. Провери че съществуват минимум 5 Entities, 5 Views, 5 ViewModels и 5 MVC Controllers. Следващите етапи трябва да развият 4 роли, операторско потвърждаване без двойно отчитане, администраторски интерфейс, карта, известия и публично публикуване.
8. Не създавай изкуствено/псевдоуспешни логове или тестове. Изпиши реално изпълнените команди и резултатите. Обнови `docs/requirements-traceability.md` с действителния статус и кратък `E1_VERIFICATION.md`.

Критерий за готовност на Етап 1: реално създадена и мигрирана БД, компилиращо се начално приложение, документация и изследване, публикуван публичен GitHub с история и достъп на консултанта до GitHub и документа. Не обещавай пълната финална функционалност на този етап.
